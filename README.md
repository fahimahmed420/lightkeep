# Lightkeep

Concept marketing site for a fictional uptime-monitoring SaaS, built by Zordev as a portfolio project. Twenty-two routes, with the blog, changelog and docs edited in a bundled Payload CMS. See [DEMO.md](DEMO.md) for the pitch, disclosure rules and test log.

## Stack

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Payload 3 on SQLite, Zod, Resend.

## Run it

```bash
npm install
cp .env.example .env.local   # then fill in PAYLOAD_SECRET and the seed login
npm run seed                 # creates the admin user and the launch content
npm run dev
```

Open http://localhost:3007 for the site and http://localhost:3007/admin for the CMS. For a production build:

```bash
npm run build
npm start
```

## Configuration

| Variable | Purpose |
| --- | --- |
| `DATABASE_URI` | SQLite file locally (`file:./lightkeep.db`); switch to Postgres for production |
| `PAYLOAD_SECRET` | Signs CMS sessions; any long random string |
| `NEXT_PUBLIC_SITE_URL` | Canonical origin, also used by live preview |
| `RESEND_API_KEY`, `DEMO_TO_EMAIL`, `DEMO_FROM_EMAIL` | Demo-request emails; without them, development logs the request and production shows "email us" |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | Login created by `npm run seed` (development only) |

## Layout

| Path | What lives there |
| --- | --- |
| `app/(frontend)/` | The public site: one folder per route, `globals.css`, the shared legal-page template |
| `app/(payload)/` | The CMS admin and REST API, generated by Payload |
| `collections/` | CMS schema: Posts, Changelog, Docs, Media, Users, and the shared slug field |
| `components/` | Header, footer, product UI mocks (dashboard, status page, bento cells), world map, scroll reveal |
| `content/site.ts` | Navigation, plans, customers, regions and other copy that is not in the CMS |
| `lib/` | Payload client helpers and the deterministic mock monitoring data |
| `scripts/` | `seed.ts` and a tiny Markdown-to-Lexical converter it uses |

## Conventions

- Published pages revalidate on save through collection hooks; drafts are visible only to signed-in editors via `?preview=1`.
- The site is never indexed: `robots.txt`, metadata and an `X-Robots-Tag` header all say so.
- Product screenshots are real components drawn in code, not images, so they prerender and cost no JavaScript.
- Animations are opt-in: content is visible without JavaScript, and `prefers-reduced-motion` turns motion off.
- `?shots=1` hides the demo pill for screenshots.
- `npm run generate:types` regenerates `payload-types.ts` after changing a collection.
